# StudyBuddy

StudyBuddy turns study notes into lessons, quizzes, and revision plans. Text files and pasted notes are handled in the browser. Without a Groq API key, images use basic English OCR. With Groq configured, the app can identify study-worthy facts, labels, steps, and diagram relationships while leaving out visual clutter.

When creating a plan, choose how many days you have (up to 30) and enter the hours you can study on each day. StudyBuddy distributes topics across the days based on available time. If you choose more days than there are topics, the remaining days become spaced-review sessions instead of being left empty. Uploading a new image resets the daily study-hour fields to one hour per day.

With `GROQ_API_KEY` configured, the Learning room uses Groq's API and `qwen/qwen3.8-27b` for lessons, quizzes, follow-up explanations, and image analysis. Module names and section headings are retained as context. Hyphen, symbol, and numbered list items become focused lessons; comma-separated subtopics and clearly capitalized and-separated subtopics inside list items become separate pages. Short standalone lines beneath headings are also treated as individual topics, supporting pasted outlines without bullets. Longer entries are divided into sentence-aligned parts of up to about 900 characters. Study plans can contain up to 500 focused lessons, so larger syllabi are not silently reduced to a handful of module-level lessons. Each topic becomes its own lesson page, like one question per quiz page. Only the selected topic is sent to Groq, and its page is generated when opened; the next topic is not prefetched. Lessons use beginner-friendly wording, detailed bullet points, step-by-step reasoning, and one worked example, aiming for about 200 words, with each bullet under 25 words, within a 1,400-token response budget. A flowchart or concept map is added only when it helps explain a process or connected ideas. The detailed lesson is always attempted first. Only if Groq hits the token limit does StudyBuddy automatically retry, up to twice, with progressively shorter lessons. If the shorter response is also cut off, it shows only complete sentences and offers another retry. Follow-up answers provide a focused, detailed explanation and example when useful. Learners can ask for a specific part of the current topic to be explained further; that request sends only the topic's notes and the learner's question. After the lessons, StudyBuddy creates one lesson-based multiple-choice question for every topic, plus one applied problem with a worked solution. Quiz questions are generated one at a time only after the learner advances, using a small per-question token budget instead of requesting the full quiz at once. MCQs are instructed to test their assigned lesson topics with plausible distractors; repeated question stems and repeated answer choices are rejected, and the correct option position is shuffled. Learners can change a selected option until they press **Check answer**. The applied problem uses a calculation when the material supports one; otherwise it tests a practical application. Revision lists only incorrect answers and applied problems marked as needing review, showing the learner's answer, the correct answer, and the quiz explanation. After explaining a missed answer, the learner can start a follow-up quiz with one new question per reviewed weak topic; its size therefore matches the number of reviewed topics. Follow-up results show whether each explanation helped, and missed follow-up questions can be explained and checked again. Correct initial answers are not included in the revision list. Groq model availability and account limits apply. AI output can still be wrong; compare important details with the original material and trusted references. A Groq API key is required for teaching content and quiz generation; without it, the app cannot generate lessons or assessments. Study progress and extracted text are stored in the user's account database; raw image uploads are not retained by StudyBuddy. A missing key or API error is shown in the Learning room; the app does not silently substitute a planner or raw notes for generated learning content.

## Run locally

StudyBuddy uses your Supabase PostgreSQL database for accounts, sessions, study plans, and history. Python 3.9 or later is required. Install the PostgreSQL driver using `python -m pip install -r requirements.txt`. Optional AI image understanding and lesson generation use Groq's Chat Completions API through the Python backend. Image uploads still work without a Groq key using browser-based OCR, but OCR reads visible English text only; it cannot interpret diagrams or filter irrelevant text.

1. Install the Python dependency with `python -m pip install -r requirements.txt`. Copy `.env.example` to `.env` and set `DATABASE_URL` to the PostgreSQL URI from your Supabase project's **Session pooler** connection settings. To enable AI lessons, get an API key from your [Groq account](https://console.groq.com/keys) and set `GROQ_API_KEY` too:

   ```text
   GROQ_API_KEY=your-api-key
   DATABASE_URL=your-supabase-postgresql-uri
   ```

2. The server requires `DATABASE_URL` and creates its tables in Supabase automatically on startup. Keep the URI private. On Windows, double-click `start-studybuddy.bat`. It starts the server in the background without leaving a terminal window open and opens StudyBuddy in your browser. Users create an account or sign in before using the study tools. To run it in a terminal for troubleshooting, use `python server.py` from this folder.
3. The background server stays available while you use StudyBuddy. To stop it, close the `pythonw.exe` process running `server.py` in Task Manager. If you add or change the key after starting, stop and restart the server.

StudyBuddy stores account credentials (as salted password hashes), login sessions, each user's current study plan, and previous plans per account in Supabase. Its tables are created automatically at startup. The 50 most recent previous plans appear in Study history so learners can reopen their lessons and progress. The raw image file is not saved after image analysis; extracted study text is part of the user's saved study plan. Keep the database URI private and back up important data. Existing data from the old local SQLite file is not copied automatically. This local server is not reachable from other devices over the internet.

To let users sign in from anywhere, deploy the Python server to a public host, use HTTPS, set `STUDYBUDDY_HOST=0.0.0.0`, and let the host provide `PORT`. Configure `DATABASE_URL` as a private server environment variable on the host; never put it in browser code. The first version does not include email verification or password reset, so users must keep their account password safe. StudyBuddy sends images and selected lesson excerpts to Groq for analysis and generation; review Groq's data and usage policies before uploading private material.

Supported images include PNG, JPEG, WebP, and GIF. Other formats are converted to JPEG in the browser when the browser can decode them. Text uploads and pasted notes continue to work without a Groq API key.
